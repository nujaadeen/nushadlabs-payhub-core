Step 7 — Transaction History

  

    Calls GET /payments/ - a plain polling/refresh pattern, NOT websockets or
    Server-Sent Events: every trigger below (page load, the Refresh button, a successful payment
    creation in Step 5, a status check in Step 6) just re-fetches the current list from the server
    and redraws the table from scratch. That's the right amount of complexity for a manual testing
    tool where a human decides when to look - a real production UI pushing live updates to an
    actual end user might reach for websockets/SSE instead, but that's real infrastructure this
    project has no need for here.
